# 企业微信预约提醒对接

系统已支持企业微信自建应用的原生加密回调，以及预约开始前 12、6、3 小时的分级提醒。

## 企业微信后台配置

在企业微信管理后台进入自建应用的“接收消息”配置，填写：

- 回调地址：`https://www.weikebenyuan.com/api/appointments/notifications/wecom-callback`
- Token：与服务端环境变量 `WECOM_CALLBACK_TOKEN` 一致
- EncodingAESKey：与服务端环境变量 `WECOM_ENCODING_AES_KEY` 一致

保存配置时，企业微信会发起 GET 请求验证回调地址。系统会校验签名、解密 `echostr` 并返回明文。后续用户回复由同一地址的 POST 请求接收。

## 服务端环境变量

正式环境需要配置以下变量，敏感值不得写入前端、Git 仓库或日志：

```env
WECOM_CORP_ID=
WECOM_APP_SECRET=
WECOM_AGENT_ID=
WECOM_CALLBACK_TOKEN=
WECOM_ENCODING_AES_KEY=
WECOM_APPOINTMENT_URL=https://www.weikebenyuan.com
```

修改环境变量后需要重启后端服务。

## 客服账号绑定

在系统设置的账号管理中，为每位客服填写对应的企业微信 UserID。提醒只会发送给预约订单当前归属客服绑定的 UserID。

## 提醒和回复规则

- 预约开始前约 12 小时发送第一次提醒。
- 未收到确认时，在约 6 小时和 3 小时前继续提醒。
- 客服回复后，剩余提醒停止发送。
- 回复 `已通知`：系统按发送人自动匹配最近一条待确认预约。
- 回复 `已通知 预约编号`：明确确认指定预约。
- 开始前 2 小时以上确认记为“已通知”。
- 开始前 2 小时以内确认记为“延迟”。
- 服务开始后仍未确认记为“遗漏”。

提醒任务由后端定时扫描执行。原生企业微信回调会验证消息签名、解密 XML 消息，并校验消息中的企业 ID。

## 验证建议

1. 先在本地执行后端测试，验证签名、加解密和自动匹配逻辑。
2. 部署到具有有效 HTTPS 证书的公网环境。
3. 在企业微信后台保存回调配置，确认 URL 验证成功。
4. 创建一条测试预约，并临时调整预约时间验证提醒。
5. 使用绑定客服账号回复 `已通知`，检查预约列表中的通知状态。

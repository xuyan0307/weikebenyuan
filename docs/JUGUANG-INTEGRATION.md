# 小红书聚光报表集成

## 范围

- 固定分析已授权的代理子账户 `7890257`。
- 只读同步账户、计划、单元、创意、笔记、搜索词、地域、人群及简单投报表。
- 不提供广告创建、编辑、启停、调价或预算变更能力。
- 前端包含：数据总览、投放分析、搜索与关键词、内容与素材、留资与私信、人群与地域、数据同步。
- 商品与直播页面暂不建设；接口返回的相关字段不会转成独立菜单。

## 数据口径

- 聚光指标按广告归因口径展示；`私信开口`、`进线数`、`私信留资`分别使用官方报表字段，不能互相替代。
- 总览中的“有效留资”为“私信留资 + 有效表单”的分析口径，页面同时保留各来源独立明细，不宣称客户级去重。
- 平台的客户建档、体验卡和套餐成交仅按相同日期范围并列展示，不宣称已经与聚光线索完成一对一归因。
- 默认显示前一天；快捷时间包括当天、前一天、近 7 天、近 1 个月、上个月、今年和自定义时间。
- 当天的账户、计划、单元、创意数据使用官方实时接口；历史范围使用离线接口。实时接口仅查询当天，混合日期范围由后端自动拆分。
- 聚光离线报表次日上午才逐步稳定：每天 `00:10` 保存暂定数据，`10:15` 回补并标记已结算。已结算快照不会被后续暂定同步降级。

## 同步机制

- 页面打开：后台触发所选日期范围同步；同一范围 5 分钟内已完成或当前有任务时不会重复提交。
- 手动刷新：仅超级管理员和管理员可执行；接口立即返回任务已受理，前端在后台完成后自动刷新，避免长同步被网关超时中断。
- 自动任务：后端进程内每天按 `Asia/Shanghai` 在 `00:10` 和 `10:15` 执行。
- 报表按最多 30 天分段、500 行分页拉取；数据库按报表和日期范围事务性覆盖，避免官方数据修正后残留旧行。
- 同步批次、成功报表数、写入行数和错误摘要记录在 `juguang_sync_jobs`；报表原始字段保存在 `juguang_report_rows`，不保存 Token。

## 本地配置

仓库不保存真实凭据。开发机可让后端复用已授权工具的私有配置文件：

```text
XHS_JUGUANG_CONFIG_FILE=<仓库外的聚光私有 .env.local 绝对路径>
XHS_JUGUANG_ADVERTISER_ID=7890257
JUGUANG_SCHEDULER_ENABLED=true
```

私有配置文件需提供 `XHS_JUGUANG_TOKEN_FILE`；相对路径按该私有配置文件所在目录解析。

## 生产配置

生产 Compose 使用独立持久卷 `juguang_secrets`，容器内固定读取并安全写回：

```text
/app/secrets/juguang/oauth-token.local.json
```

部署前后由运维把已完成授权的 Token 文件安全写入该卷，并确认文件可由容器内 `appuser` 读写。真实 Token、App Secret 不得写进 Git、镜像、部署日志或前端环境变量。

生产环境还需通过服务端密钥配置 `XHS_JUGUANG_APP_ID` 和 `XHS_JUGUANG_SECRET`。后端会在访问令牌剩余不足 5 分钟时调用聚光官方刷新接口，并把新 access token、refresh token 及过期信息原子写回私有文件；并发请求只执行一次刷新。若 refresh token 也失效，同步任务会失败并在“数据同步”页提示重新授权。

## 权限

- 超级管理员、管理员：全部页面；手动同步。
- 财务：数据总览、投放分析。
- 客服：数据总览、搜索与关键词、内容与素材、留资与私信。
- 技师：不显示也不能访问聚光接口。

后端同时校验报表类型权限，不能依靠隐藏前端菜单绕过。

## 上线检查

1. 备份生产 RDS；确认迁移 `031_juguang_reporting` 尚未异常执行。
2. 配置账户 ID、API Base、调度开关并安全放入 Token 文件。
3. 构建前后端，执行 `backend/tests/juguangService.test.cjs` 和 OAuth 回调测试。
4. 启动后检查 `/ready`，使用管理员登录并打开“小红书聚光 > 数据同步”。
5. 确认授权账户为 `7890257`，执行前一天手动同步；主报表应成功，简单投没有数据时允许返回 0 行。
6. 分别以管理员、财务、客服账号验证菜单与接口权限。
7. 核对总览、投放计划明细中的私信开口、进线数、体验卡数量及留资来源。
8. 观察下一次 `00:10` 与 `10:15` 自动批次后再判定调度验收通过。

## 回滚

先回滚应用代码并关闭 `JUGUANG_SCHEDULER_ENABLED`。新增表不影响原业务表，可暂时保留用于审计；如必须删除，应先确认不再需要同步历史，再单独备份并处理 `juguang_report_rows`、`juguang_sync_jobs` 及迁移记录，禁止直接清空整库。

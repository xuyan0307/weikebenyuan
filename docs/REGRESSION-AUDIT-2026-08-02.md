# 整体回归与数据凭证审计报告

- 日期：2026-08-02
- 范围：首页看板、客户、订单、数据报表、技师档案、排期、预约、工资结算、合同、系统设置及企业微信预约通知
- 环境：本地前端 `http://127.0.0.1:5173`，本地后端 `/api`，MySQL 已连接，`VITE_DEMO_MODE=false`

## 1. 总体结论

核心经营链路不是静态前端演示：客户、订单、预约、排期、服务记录、工资结算、合同及首页看板均已调用后端接口并读取数据库。前后端构建通过，后端全量 88 项自动化测试通过，真实登录态 API 回归 13/13 通过。

本轮仍发现三类风险：部分页面存在仅前端保存的数据；审计日志不足以完整还原数据变更前后值；企业微信具备代码链路和公网回调入口，但当前本地环境未达到可证明的端到端送达状态。

## 3. 仅前端或部分前端功能

1. 系统设置中的通知开关只更新 React 状态，没有保存接口，刷新后无法作为系统配置或审计凭证。
2. 收支管理中的租金水电、员工工资、推广、办公及技师工资等数据使用前端初始化值；修改没有调用现有的 `/finance/income` 接口。
3. 数据报表的客服月度目标保存在浏览器 `localStorage`，没有后端持久化、权限控制和操作凭证。
4. 顶部通知角标固定为 `5`，不是后端实时数据。
5. 当前侧边栏未开放的服务记录/服务进度旧页面仍包含派生或模拟逻辑；重新开放前必须改为真实服务记录接口。

## 4. 数据凭证审计

当前已有三层证据：业务主表、服务记录/工资结算凭证、操作日志。工资结算凭证的 `evidence_snapshot` 完整，已完成预约与服务记录之间未发现孤儿记录。

仍需补强：

- 操作日志目前没有统一的业务实体 ID、变更前快照、变更后快照、请求 ID 和业务结果，无法独立还原每次修改。
- 密码修改、文件上传及自动通知任务缺少统一审计事件。
- 预约完成后再取消会形成“已服务凭证 + 已取消预约”的冲突状态，应禁止非法迁移，或生成明确的冲销凭证并保留原因、操作人和时间。
- 企业微信发送失败时会删除未发送的 delivery 记录，只在预约表留下 `notify_error`；这会丢失失败次数、重试过程和每次响应，应将失败投递永久保留。

统一验收链路定义为：`页面操作 → 后端 API → 数据库事务 → 业务凭证 → 操作审计 → 查询回读`。涉及外部通知时再增加：`投递记录 → 平台 message_id → 回调/回复 → 状态闭环`。

## 5. 企业微信预约通知核验

已确认代码链路存在：后端启动 60 秒通知调度器，调用企业微信 `gettoken` 和 `message/send`，支持加密回调 GET/POST、顾问回复匹配及预约通知状态更新；回调加解密自动化测试通过。公网回调地址可达，缺少签名参数时返回 HTTP 400，说明 TLS 和路由已部署。

当前不能判定“已打通”：

- 本地启动环境没有配置企业微信 CorpID、AgentID、Secret、Token、EncodingAESKey。
- 2 个客服顾问账号均未绑定 `wecom_userid`。
- 数据库没有成功投递记录，也没有 `message_id` 或 `sent_at` 证据。
- 手工触发同步后，一条记录提示“顾问未绑定企业微信 UserID”，另一条提示“企业微信提醒未配置”；失败 delivery 被删除。

正式验收必须使用专用测试顾问与测试客户，完成一次：预约进入需通知窗口 → 企业微信收到消息 → 顾问回复 → 回调验签成功 → 预约变为已通知 → delivery 保留 message_id、发送及回调时间。未经专用测试对象授权，不向真实客户发送测试消息。

## 8. 本轮修复与复测结果（2026-08-02）

本报告第 3～6 节记录的是修复前审计基线；以下为整改后的最终状态：

- 通知设置、客服月度目标、收支费用已经统一接入 `/api/settings` 与 `platform_settings`，取消浏览器本地存储和前端演示初始化值；写入受角色权限控制并进入操作日志。
- 顶部通知角标已改为首页待办接口实时合计；未开放的旧服务记录/服务进度模拟页面已从路由移除。
- 已完成或已经存在服务记录的预约禁止取消；历史冲突数据已通过迁移恢复为“已完成”，迁移前后快照写入操作日志。复测冲突数为 0。
- 企业微信失败投递不再删除，delivery 永久保存投递状态、尝试次数、失败摘要、最后尝试及下次重试时间；自动发送成功或失败均写操作日志。
- 操作日志补齐实体 ID、请求 ID、脱敏请求摘要和响应状态；密码修改、文件上传、自动通知与通用设置均纳入审计。
- 收支管理默认使用当前自然月份，营收汇总和订单明细使用同一月份口径；历史编辑表展示最近六个自然月，不再固定为 2025 年演示月份。
- 数据库证据检查脚本为 `scripts/check-regression-evidence.cjs`，覆盖企业微信投递字段、失败投递留存、已取消预约与服务凭证冲突、操作日志关键字段。

最终自动化结果：前端生产构建通过；后端全量测试 90/90 通过；真实登录态核心 API 回归通过；浏览器验证首页实时角标、工资结算真实数据、系统通知设置持久化与收支月份口径通过。

企业微信当前结论仍为“代码链路与失败凭证已完成，外部端到端未验收”。原因是本地环境没有可用的 CorpID、AgentID、Secret、回调 Token/AESKey，并且测试客服账号尚未绑定企业微信 UserID。配置专用测试应用与测试账号后，必须补做一次“发送成功 message_id → 顾问回复 → 回调验签 → 预约已通知”的闭环，才能标记为已打通。

## 9. 追加验收结果（2026-08-03）

- 企业微信应用配置已通过本地忽略文件注入，未写入源码、示例配置或版本库。使用明确绑定的测试 UserID 调用 `gettoken` 与 `message/send` 成功，平台返回成功状态及 `msgid`，证明“系统 → 企业微信应用消息”单向发送链路已打通。
